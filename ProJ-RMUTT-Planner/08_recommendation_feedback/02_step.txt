STEP 1  Service Foundation                                            [DONE]
  - แยก api/core/models/schemas/services/workers
  - FastAPI lifespan สร้างตารางที่ Module 08 เป็นเจ้าของ
  - request ID middleware + response envelope + validation error
  - GET /health, GET /ready, GET /metrics

STEP 2  Event Logging MVP                                             [DONE]
  POST /events
  POST /events/batch

  Contract หลัก:
    {event_id?, request_id?, student_hash?, service, action, intent?, tools?,
     latency_ms?, tokens_in?, tokens_out?, cost_est?, status?, payload?, occurred_at?}

  พฤติกรรม:
  - batch สูงสุด MAX_EVENT_BATCH (default 500)
  - event_id ใช้ idempotency; event ซ้ำไม่นับซ้ำ
  - รองรับ alias จาก Module 02: event -> action, id_hash -> student_hash
  - scrub PII ซ้ำที่ปลายทางก่อนเขียนฐานข้อมูล
  - raw student id ใน student_hash ถูก reject ด้วย 422
  - Prometheus counter/histogram สำหรับ ingest

STEP 3  Feedback + Review Queue                                       [DONE]
  POST /feedback

  Contract:
    target_type = plan | chat_message | explanation
    rating      = 1..5
    rating <= REVIEW_RATING_THRESHOLD -> review_queue

  - source_feedback_id ใช้กันการส่งซ้ำ
  - event ที่ action=feedback จาก /events/batch จะถูกแปลงเป็น feedback analytics
  - preference_signal เก็บเป็น structured JSON สำหรับส่งต่อ Module 05 ในอนาคต
  - Module 02 เป็นเจ้าของ transactional feedback/ownership check
  - Module 08 เก็บ analytical copy และ review queue ไม่เก็บ student_id จริง

STEP 4  Recommendation Output                                         [DONE]
  POST /recommendations/compose

  - รับ candidates สูงสุด 5 แผนจาก 06 และคำอธิบายจาก 07
  - รวม weekly schedule, summary, rule reasons, risks และ trade-offs
  - ไม่คำนวณเวลา/ความขัดแย้งใหม่
  - แนบ disclaimer ทุก response
  - JSON พร้อมใช้ในหน้าเว็บ

STEP 5  Alert / Notification                                          [DONE: WEB]
  POST /alerts/evaluate                    internal endpoint
  GET  /notifications/{student_hash}       internal endpoint

  A1 ลงทะเบียนล่วงหน้า 7/3/1 วัน
  A2 ที่นั่งเหลือน้อยกว่า LOW_SEAT_THRESHOLD
  A3 sec ถูกยกเลิกหรือเปลี่ยนเวลา
  A4 ใกล้วันสุดท้ายถอนภายใน 7 วัน
  A5 หน่วยกิตในแผนต่ำกว่าเกณฑ์

  - สร้าง web notification และมี dedup_key ป้องกันแจ้งซ้ำ
  - email/LINE ยังไม่ส่งจริง เพราะยังไม่มี recipient mapping/consent contract
  - Celery worker มี retention task; schedule/worker ใน Compose ให้เฟิสเชื่อม

STEP 6  Calendar Export                                               [DONE]
  GET /export/ics/{plan_id}?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD

  - อ่าน plans -> plan_items -> sections -> section_meetings
  - สร้าง weekly recurrence ด้วย Asia/Bangkok
  - รองรับหลาย meeting ต่อ section
  - คืน 404 เมื่อไม่มี plan และ 503 เมื่อ shared plan schema ยังไม่พร้อม
  - ภาพตารางยังไม่ทำ เพราะทีมยังไม่กำหนด format/endpoint ของ image output

STEP 7  Analytics Dashboard API                                       [DONE]
  GET /analytics/summary?start=&end=             internal endpoint

  คืนข้อมูล aggregate เท่านั้น:
  - events แยก action/status/service
  - P95 latency, token in/out, cost estimate
  - average rating, negative count, pending review
  - plan acceptance rate (plan rating >= 4)
  - unanswered questions และ conflict code ที่พบบ่อย

STEP 8  Privacy                                                       [DONE]
  DELETE /privacy/students/{student_hash}         internal endpoint

  - ลบ event, analytical feedback และ notification ของ hash นั้น
  - scrub nested payload: student_id/name/email/phone/password/transcript
  - retention task: feedback.purge_expired_event_logs
  - production ต้องตั้ง INTERNAL_API_TOKEN
