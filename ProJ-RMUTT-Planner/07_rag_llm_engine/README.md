## ทำไมไม่ใช้ Qdrant / sentence-transformers

คลังความรู้ตอนนี้มี 35 chunk การค้นแบบ in-memory เร็วพอและไม่ต้องพึ่ง service
ภายนอก ทำให้ CI กับเครื่องของทุกคนได้ผลเหมือนกัน และ image เล็ก

BM25 กับ TF-IDF cosine เขียนเองใน `src/core/retrieval.py`
ถ้าคลังโตเกิน ~5,000 chunk ให้เปลี่ยนคลาส `VectorIndex` ไปใช้ Qdrant + `bge-m3`
โดยไม่ต้องแก้ส่วนอื่น — interface เดิมคือ `fit(docs)` กับ `search(query, top_k)`

### การตัดคำภาษาไทย

ใช้ character n-gram ขนาด (3, 4) เลือกจากการวัดจริงกับคำถาม 14 ข้อ:

| n-gram | คะแนนต่ำสุด (คำถามที่ตอบได้) | คะแนนสูงสุด (คำถามนอกเรื่อง) | ช่องว่าง |
|---|---|---|---|
| (2,3) | 0.2451 | 0.2423 | +0.0028 |
| (3,) | 0.2192 | 0.2178 | +0.0013 |
| **(3,4)** | **0.2233** | **0.1968** | **+0.0265** |
| (4,) | 0.1721 | 0.1754 | −0.0034 |

ช่องว่างกว้างสุด = แยก "ตอบได้" ออกจาก "ตอบไม่ได้" ชัดสุด จึงตั้ง `MIN_SCORE=0.21`

## กฎเหล็กของโมดูลนี้

1. **ห้ามคำนวณเวลาหรือหน่วยกิตเอง** — ตัวเลขทุกตัวมาจากโมดูล 05 และ 06
   (มีเทส `test_never_invents_numbers` กันการถดถอย)
2. **ไม่มีหลักฐาน = ไม่ตอบ** — คะแนนต่ำกว่าเกณฑ์จะตอบว่าไม่พบ ไม่เรียก LLM เลย
3. **ทุกคำตอบที่อ้างระเบียบต้องมี `sources`**
4. **ทุกคำตอบต้องมี disclaimer**
