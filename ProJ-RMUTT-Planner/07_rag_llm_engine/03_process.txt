ลำดับการทำงาน: ตอบคำถาม (POST /generate)
  question
   -> _expand_query()  ขยายคำถามสั้นให้ค้นเจอง่ายขึ้น
   -> hybrid search (BM25 + TF-IDF) -> RRF -> กรอง doc_type/ปีหลักสูตร/program
   -> ถ้า top score < MIN_SCORE  ==> ตอบ "ไม่พบข้อมูล" จบเลย ไม่เรียก LLM
   -> build prompt (เอกสาร + context จากระบบ + คำถาม)
   -> LLM generate
   -> แนบ sources[] + disclaimer

ลำดับการทำงาน: อธิบายแผน (POST /explain/plan)
  รับ {term, plan[], conflicts[], warnings[], total_credits}
   -> แยก ERROR ออกจาก WARNING
   -> ตรวจหน่วยกิตตามเทอม (ปกติ 9-21 / ฤดูร้อน <=9)
   -> เรียบเรียงทีละข้อ: ชื่อปัญหา + รายละเอียดที่ 06 ส่งมา + คำแนะนำ + ตัวเลือก
   -> ดึงระเบียบที่เกี่ยวข้องมาแนบเป็น sources
   -> คืน verdict: ok | warning | blocked

CONTRACT ที่ต้องไม่เปลี่ยนโดยไม่บอกทีม
  โมดูล 03 เรียก 2 อันนี้ (ดู 03/src/tools.py)
    POST /knowledge/search  {query, top_k}
        -> {ok, query, found, chunks[{doc_id,title,section,doc_type,score,text}], top_score}
    POST /generate          {question, context}
        -> {ok, answer, sources[], grounded, provider, disclaimer}
  ถ้าจะแก้ ต้องแจ้งเจ้าของ 03 (Automatic28m) และ 02 (fffalafair) ก่อน

กฎเหล็ก
  1. โมดูลนี้ห้ามคำนวณเวลาหรือหน่วยกิตเอง ตัวเลขทุกตัวมาจาก 05 และ 06
     (มีเทส test_never_invents_numbers กันการถดถอย)
  2. ไม่มีหลักฐาน = ไม่ตอบ ห้ามให้ LLM เดาจากความรู้ทั่วไป
  3. ทุกคำตอบที่อ้างระเบียบต้องมี sources
  4. ทุกคำตอบต้องมี disclaimer ว่าไม่ใช่การยืนยันจากมหาวิทยาลัย

ข้อควรระวังที่เจอมาแล้ว (อย่าทำซ้ำ)
  - อย่าใช้คะแนน RRF เป็นเกณฑ์ "พบ/ไม่พบ" เพราะอันดับ 1 ได้คะแนนเท่ากันเสมอ
    ให้ใช้ cosine similarity แทน
  - คำที่ใช้ขยายคำถามต้องยาวพอ ห้ามใช้คำสั้นอย่าง "ชน" เพราะไปพ้องกับ "ชนะ"
    ทำให้คำถามนอกเรื่องถูกดันคะแนนจนผ่านเกณฑ์ (มีเทสกันไว้แล้ว)
  - เอกสารคนละปีหลักสูตรมีกฎต่างกัน ต้องกรองด้วย effective_year เสมอ

PRIVACY
  - โมดูลนี้ไม่เก็บข้อมูลนักศึกษาลงดิสก์ รับ context มาใช้แล้วจบใน request
  - ก่อนส่ง context ให้ LLM บนคลาวด์ ผู้เรียก (02/03) ต้อง mask ชื่อ-รหัสจริงมาก่อน

  - ทำชุดคำถามวัดผล 50 ข้อพร้อมเฉลย วัด recall@6 และความถูกต้องของ citation
