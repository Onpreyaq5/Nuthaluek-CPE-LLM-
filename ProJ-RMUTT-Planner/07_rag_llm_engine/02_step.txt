[x] STEP 1  โครงสร้างเอกสารความรู้
        เขียนเอกสารจำลอง 4 ไฟล์ พร้อม frontmatter (doc_type/effective_year/program_ids)
        เพื่อให้กรองตามปีหลักสูตรและประเภทเอกสารได้

[x] STEP 2  Ingest pipeline
        อ่าน .md -> แยก frontmatter -> ตัดตามหัวข้อ markdown -> หั่น chunk 900 ตัวอักษร
        overlap 150 โดยพยายามตัดที่ท้ายบรรทัด ไม่ตัดกลางประโยค
        ผลตอนนี้: 4 ไฟล์ -> 35 chunk

[x] STEP 3  Hybrid retrieval
        BM25 (เขียนเอง รองรับ tokenizer ไทย) + TF-IDF cosine
        รวมอันดับด้วย Reciprocal Rank Fusion (k=60)
        ** คะแนนที่คืนออกไปคือ cosine (0-1) ไม่ใช่คะแนน RRF **
        เพราะ RRF ให้คะแนนตามอันดับ ผลอันดับ 1 จะได้ 0.0328 เท่ากันหมด
        ใช้เป็นเกณฑ์ตัด "ไม่พบข้อมูล" ไม่ได้ (เคยพลาดตรงนี้มาแล้ว)

[x] STEP 4  ปรับ tokenizer ภาษาไทย
        วัดจริงกับคำถาม 14 ข้อ (เกี่ยวข้อง 9 + นอกเรื่อง 5) เทียบ n-gram 4 แบบ
        (2,3)=gap +0.0028 / (3,)=+0.0013 / (3,4)=+0.0265 / (4,)=-0.0034
        เลือก (3,4) เพราะแยกคำถามที่ตอบได้ออกจากคำถามนอกเรื่องได้ห่างสุด
        ตั้ง MIN_SCORE=0.21

[x] STEP 5  กันการมั่ว 3 ชั้น
        1. คะแนนต่ำกว่า MIN_SCORE -> ตอบ "ไม่พบข้อมูล" ไม่เรียก LLM เลย
        2. prompt สั่งให้ตอบเฉพาะจากเอกสาร + อ้างหมายเลขเอกสาร
        3. ทุกคำตอบแนบ sources กลับไปเสมอ

[x] STEP 6  โหมด LLM
        rule_based (ค่าเริ่มต้น) - เรียบเรียงจากข้อความในเอกสารตรง ๆ ไม่ต้องมี API key
        gemini / openai / anthropic - เปิดเมื่อใส่ LLM_API_KEY
        provider จริงล้ม -> fallback กลับ rule_based อัตโนมัติ ไม่ทำให้ผู้ใช้ค้าง

[x] STEP 7  Explainer (ต่อกับโมดูล 06)
        รับ conflicts[] / warnings[] แบบ structured จาก 06 แล้วแปลงเป็นภาษาคน
        แปลง day=0 -> "วันจันทร์", 540 -> "09:00" ตามที่ 06 ส่งมา
        ** ไม่คำนวณเวลาหรือหน่วยกิตเองเลย **
        ตรวจกติกาหน่วยกิต 9-21 (ฤดูร้อน <=9) แล้วบอกว่าต้องเพิ่ม/ถอดกี่หน่วยกิต

[x] STEP 10 แก้บั๊กจากการทดสอบแบบผู้ใช้ (user test 12 คำถาม พบปัญหา 12/12)
        B1 sources ที่แนบกลับไม่ตรงกับเอกสารที่คำตอบใช้จริง
           โหมด rule_based ยกข้อความมา 3 ชิ้น แต่แนบ sources 6 ชิ้น
           ผู้ใช้เห็นแหล่งอ้างอิงที่ไม่เคยถูกอ้างถึงเลย
           -> llm.generate() คืนรายการเอกสารที่ใช้จริงมาด้วย
        B2 ลำดับผลลัพธ์ไม่ตรงกับคะแนนที่แสดง (อันดับ 2 คะแนนสูงกว่าอันดับ 1)
           เพราะเรียงด้วย RRF แต่โชว์คะแนน cosine
           -> ใช้ RRF แค่คัดผู้เข้ารอบ แล้วเรียงด้วยคะแนนที่แสดงจริง
        B3 /knowledge/search กับ /generate ให้ผลต่างกันสำหรับคำถามเดียวกัน
           เพราะขยายคำถามเฉพาะใน /generate
           -> ย้าย expand_query ไปที่ knowledge.search ใช้ร่วมกันทั้งสองทาง
        B4 ค้นด้วยรหัสวิชา/ชั้นปี แล้วได้ผิดอัน
           - chunk ตารางหลักสูตรยาว TF-IDF หารคะแนนตก
           - เลขชั้นปี "2" กับ "4" เป็น token ที่เจอทุกที่ IDF เกือบศูนย์
             ถาม "ปี 2 เทอม 1" ได้ "ชั้นปีที่ 4 ภาคการศึกษาที่ 2"
           -> breadcrumb หัวข้อ (ชั้นปีที่ 2 > ภาคการศึกษาที่ 1) + ตัวคูณคะแนน
challenge ที่เจอระหว่างแก้: ตอนแรกใช้ "บวก" คะแนน ทำให้คำถามนอกเรื่อง
        "ปี 2 นี้หุ้นตัวไหนน่าซื้อ" ทะลุเกณฑ์ เปลี่ยนเป็น "คูณ" จึงขยายเฉพาะ
        chunk ที่เกี่ยวข้องอยู่แล้ว (ช่วงที่ใช้ได้ 1.9-2.4 วัดจากข้อมูลจริง)
