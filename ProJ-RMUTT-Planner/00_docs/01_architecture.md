## 2. ตารางเทียบ: ไดอะแกรมต้นแบบ → โมดูลในโปรเจกต์นี้

| กล่องในไดอะแกรม (รูปที่ 2) | โมดูล | พอร์ต |
|---|---|---|
| Web App (Frontend) | `01_web_app` | 3000 |
| API / Backend | `02_api_backend` | 8000 |
| AI Router / Agent | `03_ai_router_agent` | 8100 |
| General AI (Gemini/OpenAI) | เรียกจาก 03 / 07 | (cloud) |
| Local AI Model | `local_ai` (Ollama) | 8300 |
| University RAG + Retrieval/Knowledge | `07_rag_llm_engine` + Qdrant | 8700 / 6333 |
| LLM Generation | `07_rag_llm_engine` | 8700 |
| User Data / Context | `05_data_integration` | 8500 |
| Knowledge Base (University Data) | `04_course_data_services` + `/data` | 8400 |
| Response / Log + Monitoring & Analytics | `08_recommendation_feedback` | 8800 |
| **(เพิ่มสำหรับโปรเจกต์นี้)** ตรรกะตารางชน | `06_schedule_conflict_engine` | 8600 |

> กล่อง 06 คือส่วนที่ไดอะแกรมต้นแบบไม่มี แต่เป็น **หัวใจ** ของโจทย์ "ดูตารางชนได้"
> และต้องเป็นตรรกะล้วน ไม่ใช้ LLM — เพราะคำตอบต้องถูก 100% และทำซ้ำได้

## 3. หลักการออกแบบที่ทีมต้องยึด

1. **LLM ไม่ตัดสินเรื่องเวลา** — เรื่องชน/ไม่ชน/หน่วยกิต คำนวณด้วยโค้ดใน 06 เท่านั้น
   LLM มีหน้าที่ "อธิบาย" และ "คุยกับคน"
2. **ทุกคำตอบเชิงระเบียบต้องมีแหล่งอ้างอิง** — ผ่าน RAG เท่านั้น ไม่มีหลักฐาน = ไม่ตอบ
3. **หนึ่งโมดูล = หนึ่ง container = หนึ่งคน/หนึ่งทีมย่อยดูแล** — แก้ไม่ชนกัน merge ง่าย
4. **สัญญา (contract) ระหว่างโมดูลต้องนิ่งก่อนเขียนโค้ด** — คุยกันที่ `03_process.txt` ของแต่ละโมดูล
5. **ข้อมูลนักศึกษาเป็นข้อมูลส่วนบุคคล** — PDPA, mask ก่อน log, mask ก่อนส่ง cloud LLM
