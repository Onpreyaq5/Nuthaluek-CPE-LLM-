LAYER
  src/api/v1 (router, FastAPI-aware)
    → src/services (business, ห้าม import fastapi)
    → src/repositories (DB เท่านั้น, SQLAlchemy) / src/adapters (interface + mock|inprocess|http ของ 03-08)
    → src/models (SQLAlchemy ORM)
  ห้าม router เรียก DB ตรง, ห้าม service รู้จัก HTTP (fastapi/starlette)

RESPONSE CONTRACT (ทุก endpoint ยกเว้น /health /ready /metrics และ /chat ซึ่งเป็น SSE)
  { "ok": true,  "data": {...}, "meta": {"request_id": "req_...", "took_ms": 0} }
  { "ok": false, "error": {"code","message","details"}, "meta": {"request_id": "req_...", "took_ms": 0} }
  HTTP status ตรงกับ code เสมอ · ทุก response มี header X-Request-ID
  error code: AUTH_401, FORBIDDEN_403, NOT_FOUND_404, CONFLICT_409, PAYLOAD_413, VALIDATION_422,
              RATE_429, UPSTREAM_502, INTERNAL_500

REQUEST FLOW (/api/v1/plans/validate)
  1. auth dependency → ดึง student_id จาก JWT ใน cookie "session"
  2. rate_limit dependency (ก่อนถึง router เสมอ ผ่าน app.include_router(..., dependencies=[Depends(rate_limit)]))
  3. โหลด section ที่เลือกจาก adapter 04 (course_catalog, cache ผ่าน redis)
  4. เรียก adapter 06 (plan_engine) {student_id, term, section_ids} → conflicts[] + prereq issues[]
  5. normalize → ตอบ frontend ตาม envelope ด้านบน
  06 ล่ม/timeout → UPSTREAM_502 {"module": "06"} (ไม่ครอบ retry ใน 02 เกินตารางที่ตั้งไว้ใน .env)

REQUEST FLOW (/api/v1/chat) — SSE, ไม่มี envelope
  1. auth dependency + rate_limit (scope "chat" แยกจาก general)
  2. resolve session (ใหม่ถ้า session_id เป็น null, ถ้าไม่ใช่ต้องเป็นของ student คนนี้เท่านั้น → 403/404)
  3. enrich payload (mask ชื่อ/รหัสจริงด้วย masking.hash_student_id ก่อนส่งออกนอก 02) → POST adapter 03 (stream)
  4. "peek-first-event" ก่อนเปิด StreamingResponse จริง: เรียก __anext__() ครั้งแรกนอก stream, ถ้าพัง (03
     ไม่ตอบ/error ตั้งแต่ต้น) → ตอบ 502 แบบ envelope ปกติ ไม่ยิง SSE เลย; ถ้าสำเร็จ 02 ยิง event "session"
     ของตัวเองก่อน แล้วค่อย proxy event ที่เหลือทีละตัว (sanitize ทุก event ผ่าน allowlist ก่อนส่งต่อ)
  5. client ตัด connection (CancelledError) ระหว่างส่ง token → บันทึกเฉพาะ token ที่ยิงไปแล้วจริงก่อน cancel
     (bookkeeping ต้องอยู่ก่อน yield เสมอ ไม่งั้น token สุดท้ายที่ client ได้รับจะหายจาก DB)
  6. จบสตรีมแล้วบันทึก message + sources ลง DB (status: complete | interrupted | cancelled)

SECURITY / PDPA
  - ห้าม log ชื่อ/รหัสนักศึกษาจริง หรือเนื้อไฟล์ import/ข้อความแชต → ใช้ masking.hash_student_id() /
    masking.scrub_text() / masking.mask_payload() ก่อน log และก่อนส่งออกนอก 02 (ไปยัง 03)
  - ไฟล์ import (transcript HTML) parse แล้วทิ้งทันที ไม่เก็บไฟล์ดิบ
  - ทุก query ใต้ /students/me, /plans, /chat กรองด้วย student_id ของ session เสมอ (ownership: คนอื่น
    เข้าถึงของฉันไม่ได้ → FORBIDDEN_403 ไม่ใช่ NOT_FOUND_404 เมื่อ resource มีจริงแต่ไม่ใช่เจ้าของ)
  - secrets (JWT_SECRET ฯลฯ) อ่านจาก env เท่านั้น ห้าม commit .env จริง
